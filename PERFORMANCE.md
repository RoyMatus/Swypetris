# Проверка энергопотребления

## Изменения

- Игровой таймер планирует ближайшее падение или видимый шаг очистки строки. В меню,
  справке и фоне ожидающего игрового callback нет. Заставка и салют сохраняют свои
  отдельные ограниченные по времени анимации.
- Очистка сохраняет шаг 60 мс и общую длительность 600 мс; время паузы учитывается
  точно, даже между видимыми шагами. Скорость, очки и правила игры не меняются.
- Время очистки и салюта читается при рисовании, а не при композиции окружающего
  интерфейса. Тень и клетки следующей фигуры переиспользуются при прежних входных данных.
- Сохранения остаются на каждом изменении партии. Неизменившееся поле повторно не
  сериализуется, идентичные снимки повторно не записываются. Формат `session_v1` сохранён.
- Issue #2: непрерывный свайп вверх вращает один раз. Новое касание либо движение
  вниз на `max(12 dp, touchSlop)` разрешает следующий свайп вверх. Бросок и перемещение
  после длинного свайпа вверх отсчитываются от актуальной позиции пальца.

## Воспроизведение замеров

`EnergyScenarioTest` запускается только при аргументе `energyScenario=true`; обычный
набор тестов пропускает его. Сценарий использует реальный таймер, музыку «Коробейники»,
включённые звук и вибрацию, одну команду в секунду и новую партию каждые 30 секунд.
В первой половине подсказки выключены, во второй включены. Последовательность команд
одинакова; последовательность случайных фигур не фиксируется.

Сначала установить выбранный APK и совместимый APK тестов. Для каждого варианта:

```powershell
./tools/Measure-Energy.ps1 -Serial '<adb serial>' -Label baseline -Seconds 600 -Runs 3
./tools/Measure-Energy.ps1 -Serial '<adb serial>' -Label optimized -Seconds 600 -Runs 3
```

Между командами установить оптимизированный APK. Скрипт временно задаёт яркость 128,
отключает автоматическую яркость, запрашивает 60 Гц и увеличивает время отключения
экрана; исходные настройки восстанавливаются в `finally`. Устройства выбираются
только по явному serial. Тест использует отдельное хранилище.

Трассы, результаты теста, температура и состояние батареи находятся в
`app/build/energy/<label>/`. При наличии официального Perfetto Trace Processor:

```powershell
trace_processor_shell query -f tools/energy-metrics.sql app/build/energy/baseline/1.trace
```

В трассе должен присутствовать ровно один завершённый маркер
`SwypetrisEnergyGameplay` длительностью около 600 секунд. SQL считает показатели
внутри этого интервала, исключая запуск и завершение instrumentation. Лог теста
содержит доступные счётчики ART: выделенные байты, число и время сборок мусора.

## Ограничения интерпретации

- Процесс приложения включает измерительный instrumentation-код; он одинаков для
  обеих версий. Debug-сборка и синтетический сценарий не заменяют измерения обычной
  пользовательской игры в release-сборке.
- Счётчики power rails измеряют компоненты всего телефона, включая другие процессы.
  Их нельзя выдавать за точное энергопотребление только Swypetris.
- Число срезов планировщика CPU не равно числу пробуждений. Отсутствие игрового
  таймера на паузе отдельно проверяется функциональными тестами.
- Зарядка, температура, работа других приложений и случайные фигуры влияют на
  сравнение. На зарядке нельзя оценивать разряд батареи по изменению её процента.
- Фоновый процесс может замораживаться Android уже в исходной версии. Нулевой CPU
  в таком замере не доказывает отсутствие старого постоянного таймера.

## Условия итоговой серии

Pixel 7, 27 сентября 2026 года. Исходная версия — коммит
`e0689fbf4066a40e5ae416e7696d7b1ecce5d301`, новая — рабочее дерево с описанными
выше изменениями. Использован один APK тестов для обеих версий.
Контрольная серия записана в `app/build/energy/battery-baseline/`, новая —
в `app/build/energy/battery-optimized/`. APK и SHA-256 сохранены в
`app/build/energy-baseline/artifacts.json` рядом с самими сборками.

Телефон отключён от зарядки на протяжении итоговых серий. Более ранние пробные,
прерванные и зарядные замеры исключены. Порядок последовательный: сначала три
контрольных прогона, затем три новых; это не рандомизированный эксперимент.
Между сериями выполнялись UI-тесты, поэтому начальная температура различается.
Температура батареи в таблице — показания в начале и конце, а не максимум за прогон.

## Проверки реализации

Проверяются реальные пути планирования и отмены таймера, остаток гравитации после
паузы, пауза на 217-й миллисекунде очистки, изменение скорости, победа и проигрыш,
освобождение модели, совместимость сохранений, повторное разрешение поворота и
преобразование пикселей в dp при нескольких плотностях экрана.

Проверено 27 сентября 2026 года:

- `:app:testDebugUnitTest`: 60 тестов успешно; сборки приложения и instrumentation APK успешны.
- `:app:lintDebug`: 0 ошибок, 32 предупреждения.
- Изолированный эмулятор Android 35: полный прогон успешен — 65 обычных тестов,
  измерительный сценарий пропущен без специального аргумента (runner выводит `OK (66 tests)`).
- Pixel 7: в первом полном прогоне четыре UI-теста не нашли Compose-иерархию или
  игровое поле. После явного пробуждения экрана повторены классы `BrandNavigationTest`
  и `ForegroundUiTest`: все 7 тестов успешны без изменений кода приложения.
  Таким образом, все 65 обычных тестов прошли хотя бы в одном из этих прогонов;
  единого полностью успешного прогона на телефоне не было. Причина первых четырёх
  сбоев окончательно не установлена.
- Справка осмотрена на снимке экрана; новый текст о повторном повороте помещается.
