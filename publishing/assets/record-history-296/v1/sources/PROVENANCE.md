# Artwork provenance

The edit reference was `app/src/main/res/drawable-nodpi/victory_foreground.png` from Swypetris commit `7b8e1bfa5a4e6669750d53457156f565160802a8`. Two outputs were produced with the built-in `image_gen.imagegen` tool, with `transparent_background: true` and the original local PNG passed as `referenced_image_paths`. No CLI image-generation API or substitute model was used.

The originals of these two outputs are retained as `trophy-source.png` and `fruit-atlas.png`. `asset-validation.json` contains their hashes and the extraction rectangles.

Inspection found isolated background pixels with alpha exactly 1/255 crossing the atlas grid boundaries. Packaging normalized those pixels to fully transparent, kept all pixels with alpha >= 2 unchanged, sliced the eight cells, trimmed transparent margins and added four transparent pixels around each fruit. No visible pixels were redrawn, resampled or recolored during packaging. The original generated files are retained unmodified for audit. The app should import only the prepared runtime PNGs, not perform extraction or generation again.

## Trophy edit prompt

Use case: precise-object-edit. Asset type: transparent Android game trophy PNG, a layer extracted from the supplied existing game artwork. The supplied image is the edit target, not a loose style reference. Remove every fruit, every leaf and fruit stem from the bottom. Leave only the exact same block-built trophy, including its full stem and stepped gold pedestal. Preserve the existing trophy silhouette, perspective, both angular handles, square block pattern, exact placement of red, purple, green and blue blocks inside the gold cup, gold bevels, highlights and top glint. Do not redesign, simplify, recolor, add blocks, change camera, change proportions or smooth the pixel/block edges. Restore only the small portions of the existing gold pedestal that were occluded by fruits, following its already-visible rectangular block structure. The cup must be completely fruit-free, including lower left and lower right corners. Center the complete trophy with an even small transparent margin, fully contained with no clipping. Genuinely transparent RGBA background; no background color, floor, frame, checkerboard, shadow backdrop, labels, text or numbers. A single trophy only.

## Fruit atlas edit prompt

Use case: precise-object-edit. Asset type: ONE transparent sprite atlas for an Android game, made from the eight fruit illustrations in the supplied game artwork. The supplied image is the exact edit target. Extract/reconstruct each fruit into its own isolated complete sprite, preserving its existing shiny voxel/pixel art appearance, colors, highlights, leaves, stems, silhouettes and viewing direction. Do not replace with generic emojis or the 16x16 HUD icons. No trophy or gold blocks anywhere. Create a rigid 4-column by 2-row grid on a wide transparent canvas (2:1 aspect ratio), eight equally sized square cells, with each sprite centered in its own cell and at least 12 percent transparent padding on every cell edge. Row 1 left-to-right: the pair of cherries together as ONE sprite; banana; purple grapes; strawberry. Row 2 left-to-right: red apple; green pear; pineapple; watermelon wedge. Each fruit occurs exactly once and there are no other objects. Complete occluded fruit edges faithfully; do not leave fragments of other fruits or pedestal in any cell. Each icon uses most of its cell while preserving its own aspect ratio. All eight sprites must be disconnected, fully contained within their cells; no overlap between cells. Genuine transparent alpha background. No grid lines, borders, text, labels, counts, circles, fake checkerboard or drop shadows.

These prompts document provenance only. They are not instructions for the implementation agent to regenerate the assets.
