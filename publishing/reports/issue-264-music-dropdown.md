# Settings music dropdown regression (#264)

Baseline reproduced on the real MainActivity and focusable Material3 DropdownMenu: Activity window focus became false, and the prepared menu AudioTrack changed from PLAYING (3) to PAUSED (2). The native lifecycle pause happened later during teardown. Logs recorded position 8704 before opening and 99008 after interruption; audio focus was abandoned. This establishes the current popup regression, not audio-quality issue #188.

GameViewModel now owns native Activity/popup focus and explicit opening/closing transfer acknowledgements. MusicPicker observes both windows; listeners are removed with composition disposal and the popup View is weakly referenced. Backgrounding clears transfer state. A live popup losing focus still pauses audio. Default popup focusability, keyboard/Back/accessibility behavior, geometry, songs, volume, selection semantics and GameMusic audio-focus/noisy handling are retained.

A frame-based intermediate implementation briefly entered SILENT before native focus arrived. The strengthened real-player audit detected it; the final implementation uses acknowledgements without a frame deadline. Exact Compose UI 1.7.0 sources dispose popup composition before removing its window, allowing controlled dismissal to preserve playback through return transfer.

Focused API35 verification: MusicSettingsFruitTest, MusicIntegrationTest and MenuPreparationTest passed 21 cases / zero skips in 290.792 seconds. Native cases inspect prepared AudioTrack identity and advancing head position. A delegating observer records commands to real GameMusic and rejects transient SILENT during opening, scrolling, outside dismissal, Back and same-selection paths; playlist occurrence and choice remain unchanged. Native selection/Off/persistence, notification-panel focus loss, Activity background, lock/wake, audio-focus and noisy/headphone callbacks passed. Outside tap uses Android window dispatch, native popup bounds and safe app insets.

Failing cases and XML/device/lifecycle diagnostics remain in ignored output. Audio callbacks use real Android players; no physical-headphone or acoustic listening test is claimed. Pixel 7 was not used. The mandatory exact-head/current-base PR gate is separate; see the PR for its final result.

API references: [Compose menus](https://developer.android.com/develop/ui/compose/components/menu), [window focus observer](https://developer.android.com/reference/android/view/ViewTreeObserver.OnWindowFocusChangeListener), [system accessibility actions](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [exact UI 1.7.0 source artifact](https://dl.google.com/dl/android/maven2/androidx/compose/ui/ui-android/1.7.0/ui-android-1.7.0-sources.jar).
