# Android implementation

Locate the existing owner of the affected rule, UI state or saved session. Keep game rules out of UI code where the current architecture permits; use [AGENTS.md](../../../AGENTS.md) for design, portrait, gameplay and API-research constraints.

Select checks with `android-test-selection` and use the [TDD procedure](../../../TESTING.md#tdd-for-behavior-changes). Reuse the assigned host profile, resource reservation and check plan rather than restarting discovery.

Before replacing graphics or pixel assertions, inspect source alpha/coverage and production scaling/filtering. Compare filtered output with a like-for-like oracle; retain independent source, geometry, layering, clipping, migration and state assertions. At a development checkpoint, exercise affected photo, field, HUD and Next rendering cases and relevant neighbors; mandatory final gates remain separate.

Check affected state across recomposition, navigation, backgrounding, configuration changes and restored sessions. Return changed behavior/files, actual checks and unresolved risks to the integration owner.
